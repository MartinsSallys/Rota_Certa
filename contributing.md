# Contribuindo com o RotaCerta

Obrigado por querer contribuir com o RotaCerta. Este projeto ainda está em fase inicial, mas toda ajuda é bem-vinda: melhorias de ideia, correções, documentação, testes e sugestões de experiência.

## Como contribuir

Existem algumas formas de participar:

- Reportando bugs ou falhas.
- Sugerindo melhorias de produto e UX.
- Melhorando a documentação.
- Revisando pull requests.
- Propondo novas funcionalidades para a solução.

## Antes de começar

Antes de abrir uma proposta ou alterar o código, vale conferir o README principal para entender o contexto do projeto e o escopo atual.

O repositório ainda está em evolução e a proposta inicial é apoiar a organização de rotas de entregas para pequenos e médios comércios.

## Fluxo de trabalho

### 1. Faça um fork do repositório

Crie seu fork e clone localmente:

```bash
git clone https://github.com/seu-usuario/rota-certa.git
cd rota-certa
```

### 2. Crie uma branch

Use uma branch com nome descritivo:

```bash
git checkout -b feature/nova-funcionalidade
```

Sugestões de nomenclatura:

- `feature/` para novas funcionalidades
- `fix/` para correções
- `docs/` para documentação
- `chore/` para ajustes de manutenção

### 3. Faça suas alterações

Mantenha as mudanças focadas e pequenas. Quanto mais específico o PR, mais fácil será revisá-lo.

Algumas boas práticas:

- descreva claramente o problema que está sendo resolvido
- evite mudanças fora do escopo
- mantenha nomes consistentes e legíveis
- priorize clareza sobre complexidade desnecessária

### 4. Valide localmente

Como o projeto ainda não possui uma aplicação completa implementada nesta fase inicial, a validação principal pode ser simples e focada na apresentação e no comportamento esperado do projeto.

Para a versão atual, o uso mais comum é abrir o arquivo HTML em um navegador:

```bash
# no Windows, basta abrir o arquivo no navegador
```

Se houver alterações em arquivos de apresentação, HTML ou documentação, verifique se:

- a estrutura não foi quebrada
- a interface continua legível
- os textos e links continuam corretos
- o comportamento esperado permanece consistente

### 5. Commit e pull request

Use mensagens de commit claras e objetivas, por exemplo:

```bash
git commit -m "feat: adiciona seção de proposta de valor"
```

Ao abrir o pull request:

- explique o problema e a solução proposta
- detalhe o contexto da mudança
- inclua screenshots ou exemplos se a alteração for visual
- descreva como validar a mudança

## Critérios para aprovação

Um pull request será mais facilmente aceito quando:

- a mudança estiver alinhada ao objetivo do projeto
- a descrição estiver clara e objetiva
- o código ou artefato alterado estiver consistente com o restante do projeto
- não houver alteração acidental em arquivos fora do escopo

## Reportando problemas

Ao abrir uma issue, tente incluir:

- descrição clara do problema
- passos para reproduzir
- comportamento esperado
- comportamento atual
- contexto do ambiente (navegador, sistema operacional, etc.)
- screenshots ou exemplos, quando fizer sentido

## Código de conduta

Contribuições devem ser respeitosas, construtivas e focadas no avanço do projeto. A ideia é manter um ambiente colaborativo, aberto e profissional.

## Dúvidas

Se você quiser propor algo novo ou discutir uma ideia antes de implementar, abra uma issue ou entre em contato com a equipe responsável pelo repositório.

Agradecemos seu interesse e sua contribuição para o RotaCerta.
